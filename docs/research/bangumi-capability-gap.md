# BangumiAgentKit 能力缺口矩阵

> PR-7A 研究交付物。矩阵比较网站产品能力、固定 v0 API、当前 semantic tool、Standalone/MCP 暴露和 renderer 表达能力；不等同于 PR-7B 的实现清单。

## 现状摘要

当前 semantic surface 已经能完成“按关键词找条目 → 看详情/剧集/角色 → 看关系 → 读取公开收藏/日历 → 更新自己的进度”的主链路，并保留 `list_operations/describe_operation/call_operation` 作为 raw fallback。缺口主要集中在四类：

1. API 已有但 semantic 没有表达的高级过滤、浏览、人物/角色收藏读和认证进度读。
2. 网站明确提供但 v0 没有的社区、完整统计、历史趋势和网页排序。
3. 多跳关系与时间窗口聚合，例如“过去 12 个月配音工作量”“系列观看顺序”。
4. 表达层只有五种卡片，不能承载结果解释、证据、置信度、长列表移动端布局和社区趋势。

## 研究结论

- 最优先补的是 API 已经提供、且无需 HTML 风险的 typed query filters 和关系聚合；raw operation 已能证明可行，但不是可用的产品契约。
- 讨论和历史增长问题没有“再加一个 API 参数”那么简单，需要持续快照、时间窗口、条款审查和明确的“不可计算”结果。
- Renderer 是能力放大器而不是数据源。先定义 query/evidence/view model，再增加模板；把缺数据渲染成空洞卡片不会提升用户价值。
