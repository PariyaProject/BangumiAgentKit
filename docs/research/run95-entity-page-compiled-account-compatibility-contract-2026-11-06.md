## Response ownership correction

A comprehensive review found early header/Location/image responses escaped
without disposal because HttpClient detached caller-abort forwarding after
headers. Awaiting stream cancellation could also replace a known cap error or
stall until the outer deadline. The transport now owns the response through
its terminal path, preserves after-header abort forwarding, then aborts and
initiates nonblocking disposal without allowing cleanup failure to replace the
primary result. Existing raw Location/image return values and aggregate paths
are preserved. The native total deadline remains active through the body.

The original ten regression tests were all RED in1.18s, including a real
loopback response that remained open. The corrected neighbor suite covers

termination. A second real-body abort regression protected NETWORK_ERROR from
becoming PARSER_ERROR. Thirteen lifetime tests plus the51 native and16 existing
transport checks pass. These finite local HTTP fixtures are not Bangumi/public,
account, model or client operations.
