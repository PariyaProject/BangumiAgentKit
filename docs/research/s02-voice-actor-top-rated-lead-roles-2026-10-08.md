## Finding

`bangumi.get_person_activity` cannot currently support an unqualified “top five highest-scored lead-role works” answer. The existing activity row has no score field and the service sorts returned rows by first-air date. Although the detail mapper already reads official `Subject.rating.score` and rating total, that data is discarded when rows are built. The activity tool also requires a recent calendar window (default 12 months; maximum 36), so it excludes older credits for an all-career question. [`PersonActivityRow`](../../packages/bangumi-core/src/models/person-activity.ts#L51), [`getPersonActivity` bounds](../../packages/bangumi-core/src/services/person-activity-service.ts#L574), [`date sort and row cap`](../../packages/bangumi-core/src/services/person-activity-service.ts#L807), and [`mapSubject`](../../packages/bangumi-core/src/services/subject-service.ts#L126).

The lead-role signal is useful but not a formal guarantee. The API’s `PersonCharacter.staff` is optional free text without an enum or documented vocabulary; the service infers `main` from substrings such as `主角`, `主役`, `protagonist`, or `main`, and keeps unmatched labels `unknown`. [`classifyVoiceRole`](../../packages/bangumi-core/src/services/person-activity-service.ts#L129) and [`mapPersonRelationCharacter`](../../packages/bangumi-core/src/services/person-service.ts#L198).

## Source contract and coverage

- Official `GET /v0/persons/{person_id}/characters` returns a bare array of `PersonCharacter`; the operation has no pagination parameters or paged total. Each relation supplies a subject ID and may supply `staff`. [Official endpoint](https://github.com/bangumi/api/blob/master/open-api/v0.yaml#L855-L871) · [PersonCharacter schema](https://github.com/bangumi/api/blob/master/open-api/v0.yaml#L3215-L3256).
- Official `GET /v0/subjects/{subject_id}` returns `Subject`, whose `rating` contains `score`, `total`, and per-score counts. The relation endpoint does not include that rating, so ranking requires detail hydration for every eligible work. [Official subject detail](https://github.com/bangumi/api/blob/master/open-api/v0.yaml#L321-L350) · [Subject rating schema](https://github.com/bangumi/api/blob/master/open-api/v0.yaml#L3556-L3760).
- `get_person_activity` defaults to 80 relations, 32 subject details, and 40 output rows; hard maxima are 120, 48, and 60. Each official response is capped at 1 MiB and detail concurrency is 4. Relation and detail caps use deterministic even-spread sampling; the service reports dropped IDs and partial state. Returned rows are then date-sorted and sliced, so downstream sorting those rows cannot recover omitted or truncated candidates. [`PersonActivityService` bounds](../../packages/bangumi-core/src/services/person-activity-service.ts#L35), [`coverage and relation/detail selection`](../../packages/bangumi-core/src/services/person-activity-service.ts#L651), [`row construction and date sort`](../../packages/bangumi-core/src/services/person-activity-service.ts#L771), [`coverage model`](../../packages/bangumi-core/src/models/person-activity.ts#L155).
- `/v0/search/subjects` can sort search results by score, but its documented filters do not connect subjects to a person’s voice-role relations; it cannot provide this join or prove lead-role membership. [Official search schema](https://github.com/bangumi/api/blob/master/open-api/v0.yaml#L14-L140).

## Minimal change and acceptance scope

Add an explicit all-time, score-ranked lead-voice query path (or a clearly separate ranking mode) that reuses the public character relations and subject details. Carry official `rating.score` and `rating.total` into the result, conservatively select only recognized `main` labels, and sort by score with a deterministic tie-break. Do not apply the activity date window or chronological row slice to this ranking. Preserve raw role labels and expose missing/zero score, unknown role, failed detail, and coverage counts.

Accept the S02 answer as “top five” only when the current relation response and all eligible work details fit the configured caps, roles are classifiable, and ranking coverage is complete. If a cap, failed detail, or unknown role leaves candidates unresolved, return a partial result phrased as the highest-scored works in the observed bounded sample; do not claim a career-wide top five. A concise regression set should cover descending score/tie order, main versus support/unknown labels, missing scores, one complete under-cap case, and an over-cap or failed-detail case that forces partial/sample wording. Existing tests already exercise a main-role row, deterministic relation sampling, and partial truncation, but do not assert score projection or ranking. [`main-role fixture`](../../tests/unit/person-activity.test.ts#L225) · [sampling case](../../tests/unit/person-activity.test.ts#L759) · [truncation/unknown-role case](../../tests/unit/person-activity.test.ts#L892).
