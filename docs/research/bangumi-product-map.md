# Bangumi 产品与数据表面地图

> PR-7A 研究交付物。资料以 2026-08-09 可访问的公开页面、仓库锁定的 v0 OpenAPI 和当前 AgentKit 代码为准。本文是产品/数据设计研究，不是 PR-7B 实现方案。

## 研究边界与证据

主要入口：

- [Bangumi 首页/新版导航](https://next.bgm.tv/)
- [动画浏览器](https://bgm.tv/anime/browser/web?sort=trends)

“官方 API”指仓库固定的 `openapi/upstream/v0.yaml`；“HTML”指网页公开内容或页面上由浏览器加载的内容。两者不能因为字段名称相似就视作同一契约。网页的排序、显示数量、登录态和实验性入口可能变化。

## 认证与数据边界

- 公共读取适合默认查询：条目、剧集、角色、人物、关系、公开用户资料和公开收藏。
- 当前用户 episode collection、写入收藏/进度、目录编辑、评论/发帖、Wiki 编辑属于认证或写入边界；不能用公开 HTML 代替用户授权。
- “能在网页看到”不等于“有官方 API”：评论、长评、板块、Rakuen、小组、日志、主页趋势和完整统计目前应视为 HTML/衍生数据。
- 任何社区 provider 都需要显式来源、抓取时间、缓存状态和降级说明；不应把 HTML 解析结果伪装成官方 API 字段。

## 产品结论

Bangumi 的核心产品不是单一条目查询，而是一个以 subject 为中心、向 episode/character/person/user/community/series 多图扩展的发现与记录系统。PR-7B 的最小高价值切入点应先补齐结构化 API 已经支持但 semantic layer 尚未表达的高级搜索、浏览器/季节排序和 person/role 关系；社区 HTML 与个人分析应在明确 provider、认证和证据边界后再进入路线图。
