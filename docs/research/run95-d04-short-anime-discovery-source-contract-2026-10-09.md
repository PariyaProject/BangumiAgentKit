## Contract and query

`POST /v0/search/subjects` is marked experimental. Its documented server filters include `type`, `tag`, and `rating_count`; filter dimensions are ANDed. The operation has no OpenAPI security requirement, and the repository’s `bangumi.query_subjects` tool is unauthenticated and sets evidence scope to `public`. Use `keyword: ""` with the exact filters: the schema requires a string but sets no non-empty constraint, and the local compiler defaults an omitted keyword to empty. A checked-in earlier source/probe note records an empty-keyword request returning HTTP 200; that observation is dated and the experimental endpoint may change. [Official search schema](https://raw.githubusercontent.com/bangumi/api/master/open-api/v0.yaml) · [local OpenAPI copy](../../openapi/upstream/v0.yaml#L14-L97) · [query tool](../../packages/tools/src/definitions/discovery-tools.ts#L166-L180) · [local request compiler](../../packages/discovery/src/compiler.ts#L91-L127) · [earlier source/probe note](../discovery/upstream-behavior.md#L130-L136)

Use `type: [2]` (`anime`), literal `tag: ["科幻"]`, and `rating_count >= 3001`, which represents the strict integer threshold “more than 3000.” The local query form is `media: "anime"`, `tags: ["科幻"]`, `ratingCount: { min: 3001 }`; the compiler serializes the minimum as `>=3001`. The search schema does not list `eps` as a filter. Although `meta_tags` appears as a request property, it is absent from the operation’s explicit supported-filter list; this query relies on the documented `tag` filter. The search response is `Paged_Subject`, whose `data[]` items reference the full `Subject` schema. That schema requires both `eps` and `total_episodes`: `eps` is parsed by the legacy server from Wiki data (for books, it means chapter count); `total_episodes` is the number of chapter rows in the database. For this wording, compare `eps < 13` locally; do not substitute `total_episodes`. The spec defines no further accuracy guarantee for the Wiki-derived `eps` value. [Official response and Subject schema](https://raw.githubusercontent.com/bangumi/api/master/open-api/v0.yaml) · [local response schema](../../openapi/upstream/v0.yaml#L2983-L3004) · [local `eps` and `total_episodes` definitions](../../openapi/upstream/v0.yaml#L3572-L3644)

Treat `科幻` as an exact Bangumi tag proxy. The API describes `tag` as a label and says `meta_tags` are Wiki-maintained; it provides no science-fiction ontology. The local exact-concept vocabulary also has no `科幻` entry, so pass `tags: ["科幻"]` directly instead of `concepts: ["科幻"]`; do not imply synonyms or all science-fiction works are covered. ## Local implementation gap and coverage

The provider discovery candidate and its parser keep rating count, tags, and metadata but discard `eps` and `total_episodes`. The discovery query schema and result item also have no episode-count field, and the evaluator has no episode predicate. `ProviderSubjectData` does carry both fields, but that does not make them available to the discovery query. As checked out, `bangumi.query_subjects` cannot faithfully apply or display D04’s `eps < 13` test. For a bounded source-level attempt, use `resultMode: "all"`, `limit: 100`, then apply `eps < 13` to returned raw `Subject` rows while preserving missing/invalid values as unresolved. The repository defaults cap work at 10 pages, 500 candidates, 120 hydrations, and 100 returned items; it compiles search pages at up to 50 rows. Search totals are recorded as estimated, and budget exhaustion or output clipping must remain partial.
